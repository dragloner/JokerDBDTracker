# Проверка плеера 1.4.8

## Подтверждённые дефекты и исправления

| Дефект | Причина и исправление | Проверка |
|---|---|---|
| Звуки не возвращались к нейтральным настройкам после сброса | Синхронизация soundboard зависела от успешного применения видеоэффектов. Теперь это отдельное обновление, выполняемое до проверки видеокеша. | Исполнение реальных скриптов и тест WebView2 |
| Сброс ошибочно считался неуспешным | В нейтральных ветках JavaScript возвращал `undefined` вместо `true`. Исправлены результаты обеих веток. | Нейтральное состояние видео в JS-тестах |
| Повторный запуск звука использовал старые параметры | `currentParams || новыеПараметры` сохранял первый снимок. Теперь старт получает актуальный снимок, а декодирование использует последние синхронизированные значения. | Питч звука, сброс, остановка и новый запуск |
| Промежуточные состояния сброса отправлялись в WebView | Каждый из сбрасываемых контролов вызывал обновление. События подавляются на время одной операции, затем отправляется итоговое состояние. | Анализ обработчиков, проверка итоговых скриптов |
| Звук мог начаться после общего сброса | Запрос ещё читал файл до отправки в JavaScript. Сброс и навигация теперь инвалидируют такой запрос. Общий сброс останавливает и нативные, и Web Audio звуки. | Защита поколения запросов; отмена декодирования в JS |
| Старое декодирование перезаписывало новое | Общий булев флаг очищался в `finally` устаревшего запроса. Состояние теперь принадлежит конкретному поколению запроса. | Отмена и немедленный повторный запуск |
| Счётчик активных звуков уменьшался повторно | Остановка и последующее событие `ended` вычитали один и тот же звук. Завершение теперь пересчитывает число действительных записей. | Позднее `ended` при другом активном звуке |
| Изменение эквалайзера повторно создавало тяжёлый буфер реверберации | Обработчик пересоздавал impulse response и кривую дисторшна при каждом обновлении любых параметров. Теперь они обновляются только при изменении соответствующего значения. | Повторные изменения EQ сохраняют один буфер реверберации |
| Предзагрузка могла ждать разрешения на воспроизведение | Декодирующий контекст вызывал `resume()`, хотя для `decodeAudioData()` это не нужно. Ожидание удалено. | Модель при suspended-контексте; настоящий MP3 в WebView2 |
| Ошибки асинхронного воспроизведения терялись | `ExecuteScriptAsync` не ожидал Promise звукового скрипта. Нативная кнопка теперь передаёт пользовательскую активацию через `Runtime.evaluate`, ожидает Promise, ошибки попадают в диагностику. | Интеграционная проверка WebView2 с отключённым интерфейсом DevTools |
| Питч накапливался либо не сбрасывал скорость | Ускоренная скорость принималась за исходную. Сохраняется исходная пользовательская скорость; собственные события `ratechange` распознаются по ожидаемому значению. | Пять циклов применения и сброса при исходной скорости 1.5× |
| Первое применение могло сбросить выбранную скорость | Базовая скорость инициализировалась единицей. Теперь она берётся у текущего видео. | Нейтральное состояние при скорости 1.5× |
| Эффекты оставались привязаны к старому видеоэлементу | Подключённый runtime имел безусловный приоритет, а кеш настроек скрывал замену элемента. Выбор выполняется заново; кеш дополнительно проверяет идентичность видео. Аудиоэффекты участвуют в периодической проверке даже без визуальных. | Анализ путей замены элемента; полная проверка на реальном рекламном переходе ещё нужна |
| Перемотка переставала отслеживать новый элемент после минуты | Поиск нового элемента отключался через 60 секунд и предпочитал старый runtime. Поиск действует до ухода со страницы и сбрасывает точку отсчёта при замене. | Анализ жизненного цикла обработчика |
| Нулевые координаты центра фишая заменялись на 0.5 | `value || 0.5` считал ноль отсутствующим значением. Используется явная проверка конечного числа. | Анализ граничного значения |
| Другие фильтры исчезали при недоступном post-FX слое | Владение изображением определялось включённым флагом, а не видимостью слоя. Базовые фильтры сохраняются, когда overlay не отрисован. | Анализ резервного пути отрисовки |
| Панель меняла ширину после скрытия и показа | В обработчике оставалось отдельное значение 420. Используется согласованная ширина 390. | Проверка макета и обработчика |

## Интерфейс

- Удалены рекламные слоганы и крупный декоративный баннер.
- Отдельные разделы «Видео», «Звук» и «Пресеты» с видимым активным разделом.
- Короткие названия звуков, компактнее заголовок и верхняя панель.
- Горячие клавиши доступны в подсказке заголовка; длинные пояснения не занимают постоянное место.
- Макеты просмотрены при 1440×900 и 1100×720. На небольшом окне звуковые параметры прокручиваются.

## Проверки и границы вывода

30 регрессионных тестов выполняют реальные генерируемые JavaScript-скрипты на моделях DOM/Web Audio и проверяют профиль, таймкоды и установщик. Отдельный `tests/WebAudioIntegration` проверяет настоящее декодирование MP3, запуск AudioContext из нативного действия и сброс питча играющего звука в WebView2. Он использует изолированный профиль и отключённый звуковой выход.

Это не доказательство отсутствия всех возможных дефектов. Ранее описанный периодический чёрный экран со звуком, пропадающим на отдельных стримах, не воспроизведён в контролируемом тесте. Не объявляется исправленным; для него доступны события `Player.Media` и `Player.MediaNetwork`. Проверки моделей не заменяют длительный просмотр реальных YouTube/Twitch стримов, рекламы и всех аппаратных декодеров.
